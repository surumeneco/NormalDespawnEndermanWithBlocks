# 実機確認・受入テスト手順（Paper 26.2 / Java 25）

**状態**：運営による実機確認待ち。CI・JUnit Greenはゲーム内検証や負荷計測の代わりではない。

## 導入前

1. `develop` に統合された最新版のJARを取得し、バックアップした検証用Paperサーバーを停止する。
2. 古い `normal-enderman-despawn-1.0.0.jar` を **必ず撤去**。旧版と新規版の二重実行はしない。
3. `NormalDespawnEndermanWithBlocks-1.0.0.jar` を `plugins/` に配置し起動する。
4. ログにプラグインの有効化が出ること、`/plugins` に新しい名前だけが表示されること、エラー/WARNがないことを確認する。
5. `plugins/NormalDespawnEndermanWithBlocks/config.yml` が正しく生成されることを確認する。変更は**再起動**後に適用される。

## 決定的な最小試験

**本番値を変更している間は必ず検証用サーバー限定**。次の検証用設定で再起動する。

```yaml
soft-distance: 32.0
hard-distance: 128.0
minimum-far-ticks: 0
random-chance-denominator: 1
scan-interval-ticks: 20
```

- ブロックを所持する、**名前のない**エンダーマンを、同じワールドの有効な非スペクテイターのプレイヤーから約 **16ブロック** に置く。複数スキャン（2秒以上）後も消えないこと。
- 同条件で約 **40ブロック** に置く。約20tick以内の次スキャンで削除されること。自然スポーンMobが移動するため、観察中の位置関係を維持する。
- 同条件で約 **129ブロック** に置く。次スキャンで削除されること。該当チャンクが読み込まれている必要がある。
- ブロック**非所持**のエンダーマンはプラグインにより即時削除されないこと。
- ブロック保持でも**名前付き**・`removeWhenFarAway=false`・乗車/乗客の対象は保護されること（他のプラグインと設定が関わる場合は併せて観察）。
- 当該ワールドに **スペクテイターしかいない**、またはプレイヤー不在でチャンクがロードされている場合、難易度がPeacefulでなければ距離を理由に削除されないこと。
- 難易度Peacefulでは、非保護のブロック保持エンダーマンが削除されること。

設定をデフォルト（`minimum-far-ticks: 600`, `random-chance-denominator: 800`）に戻し、実際の通常難易度で正常に動作することを確認する。確率的な試験では1件が一定時間生存しても不具合と断定しない。

## 負荷と副作用

- 同条件の参加人数とロード済みエンダーマン数で、導入前後のTPS/MSPT・CPU使用率・GC傾向を比較する。サンプル数・観測時間を記録する。
- エンダーマンのブロック取得・設置・移動・攻撃・テレポートが従来通りであることを確認する。
- ワールド間移動、チャンクアンロード/再ロード、サーバー再起動後のカウンタ再初期化と、他プラグインの保護設定との共存を確認する。
- 例外が出た場合は起動ログ、検証時の最新ログ、関係する個体の状況を記録する。

## 合格条件と境界

受入時点までは`main`へのマージ/正式リリース/本番配備は行わない。CATが生成した8分岐の有限モデルの適合は、ランタイムのチャンク・プレイヤー・Paper連携の統合証拠とは区別する。

- **正常**：上記の決定的ケースが期待通り、重大ログなし、MSPTが運営の許容範囲内。
- **差戻し**：明示的保護個体の消失、対象外個体の削除、起動エラー、許容不能な負荷悪化、仕様に反する挙動。
